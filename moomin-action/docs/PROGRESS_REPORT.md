# 중간 점검 보고 (2026-11-22)

3D 실시간 코인 전투 액션 RPG. Blender로 모델과 애니메이션을 만들고, Unity(C#)로 게임을 만든다. 코드는 C# 64개 파일, 약 5,200줄이다. 모델과 UI 그림을 만드는 Python 도구와 순수 로직 테스트 90개가 함께 있다.

> **가장 중요한 한계: Unity에서 실제로 실행해 본 적이 없다.** 컴파일 검사(`tools/compile_check.sh`), 로직 테스트, Blender와 Python으로 만든 미리보기 이미지로만 확인했다. 실제 플레이에서는 조작감, 카메라, 애니메이션 연결, UI 겹침, 성능 문제가 나올 수 있다.

### 전투 시스템 (핵심, 대부분 완성)

- **코인 전투:** 코인 하나가 공격 한 번이다. 정신력(−45~+45)에 따라 앞면 확률이 5~95%로 바뀌고, 위력 = 기본 + (앞면이면 코인 위력)이다. 피해 = 위력 × 배율 × 받는 피해 보정이다.
- **합(클래시):** 양쪽 공격이 동시에 겹치면 위력을 비교한다. 금빛 불꽃 충돌 → 물러남 → 재충돌 → 합 승리 연출 순서로 진행되며, 화면 가운데에 두 스킬 패널이 뜬다. 림버스식 여러 라운드 합은 선택 사항으로 남겨 두었다.
- **방어:** 가드는 피해를 50% 줄이고, 가드를 시작한 직후에 막으면 패링이다. 회피는 회피 코인 위력과 공격 위력을 비교해서, 이기는 동안 회피 상태가 유지된다.
- **광역 공격:** 원형과 직선(빔)이 있다. 코인은 한 번만 굴리고 모든 대상에게 같은 위력을 적용하며, 회피·가드는 대상마다 따로 판정한다.
- **속성 7색과 상성:** 색상환 순서로 다음 색을 이긴다(검정은 중립). 유리하면 피해 ×1.25, 합 위력 +2다.
- **상태이상 7종:** 출혈·화상·침잠·진동(경직 게이지 폭발)·힘·위력 감소·마비. 강도와 횟수를 따로 쌓는다.
- **경직 게이지와 에너지:** 에너지는 강화 스킬에 쓰는 비용이다.
- **적 AI:** 상황 점수로 접근·공격·방어·회피를 고른다. 바닥에 색으로 공격을 예고한다(빨강 일반 · 파랑 합 불가 · 보라 방어 불가). 성격(일반/보스/인간형)마다 판단이 다르다.
- **성장(기초):** 경험치·레벨 곡선을 넣었다. 레벨이 오르면 최대 체력 +10이다.
- **인벤토리:** 30칸, 소모품, 무기 장착(공격력 배율·칼날 색), 퀵슬롯 4칸, 적이 떨어뜨리는 아이템과 금화. 저장은 PlayerPrefs를 쓴다.

## 2. 꼭 해결·제작해야 하는 것 (우선순위 높음)

1. **Unity에서 실제로 실행하고 오류를 고치기.** 메뉴 "Moomin ▸ 한 번에 설정"으로 씬을 만들고 플레이해서 콘솔 오류를 잡는다. 지금까지 만든 모든 것이 이 단계를 통과해야 의미가 있다.
2. **저작권 정리 (배포 전 필수).**
   - **주인공:** 잘 알려진 캐릭터(무민)를 바탕으로 만들어서, 공개하거나 판매하면 저작권 문제가 생긴다. 개인 학습용이 아니라면 **고유한 오리지널 주인공으로 바꾸는 것을 강하게 권장**한다. 지금은 뼈대와 애니메이션 구조가 모델과 분리되어 있어서, 새 캐릭터로 바꿔 끼우기 쉽다.
   - **맵:** 받은 3D 월드의 라이선스를 확인하지 못했다. 그래서 원본 파일은 저장소에서 빼 두었다.
   - 림버스 컴퍼니나 엘든 링에서 받은 영향은 규칙과 분위기뿐이고, 그림과 데이터는 모두 새로 만들었다.
3. **게임의 시작과 끝.** 지금은 바로 웨이브 전투가 시작되고, 쓰러지면 R로 다시 시작하는 것뿐이다. 타이틀 화면, 새 게임/이어하기, 게임 오버/클리어 화면이 필요하다.
4. **저장과 불러오기.** 지금은 가방과 설정만 PlayerPrefs에 저장된다. 레벨·경험치·위치·진행 상황을 슬롯별로 저장해야 한다.
5. **사운드.** 소리가 전혀 없다. 타격음, 코인 소리, 합 충돌음, 고래빔, 배경음악, UI 효과음이 필요하다.
6. **바다괴물형 적.** 처음 계획한 적 3종 중 마지막이다.
7. **맵 성능.** 맵이 면 125만 개짜리 한 덩어리다. 구역으로 나누고, 멀리 있는 물체를 단순하게 바꾸거나 가려진 물체를 그리지 않도록 처리해야 한다.
8. **밸런스 플레이테스트.** 수치는 계산과 시뮬레이션으로만 정했다. 예: 고래빔 4번 판정, 고래 체력 220, 주인공 체력 100.

## 3. RPG로서 추가가 필요한 것

지금은 '전투 액션 데모'에 가깝다. RPG가 되려면 아래가 필요하다.

| 분야 | 필요한 것 | 지금 상태 |
|---|---|---|
| 이야기·퀘스트 | 메인 줄거리, 퀘스트(목표·보상), 퀘스트 기록창 | 없음(웨이브 목표 문구만 있음) |
| NPC·대화 | 마을 주민, 대화창(선택지), 상인, 퀘스트를 주는 NPC | 없음(대화 선택지 UI 스타일만 있음) |
| 성장 | 레벨 업 때 능력치 선택이나 스킬 포인트, 스킬 습득과 교체(현재 Q/E/R 고정), 스킬 강화 | 레벨·체력 증가만 있음 |
| 장비 | 방어구·장신구, 장비 능력치(속성 저항·정신력 보정·코인 확률), 장비 화면 | 무기 배율만 있음 |
| 경제 | 상점(사고팔기), 금화를 쓸 곳, 제작이나 강화 | 금화를 모으기만 함 |
| 지역 진행 | 구역 잠금과 해제(성 → 산지 → 바다), 지역별 적과 보스, 이동 지점 | 맵 하나에 웨이브만 있음 |
| 보스전 | 보스 전용 무대, 체력에 따른 단계 변화(예: 고래고래 50%부터 빔 연사), 처치 보상 | 보스바와 기술만 있음 |
| 휴식·회복 | 체크포인트(쉼터), 회복 아이템 밸런스, 부활 지점 | 회복 아이템만 있음 |
| 편의 | 튜토리얼(코인·합·가드·회피 설명), 난이도, 키 변경 | 조작법 페이지만 있음 |

**추가를 권장하는 화면**

- **캐릭터 화면(C):** 능력치, 장비 칸, 속성 저항, 정신력 상태 설명.
- **스킬 화면(K):** 배운 스킬 목록, 슬롯 교체, 스킬 패널 미리보기를 재사용.
- **퀘스트 기록(J)과 월드맵 연동:** 지도에 퀘스트 목표 핀 표시.
- **대화창:** 기존 "» 선택지 막대" 스타일 활용.
- **상점 화면:** 가방 UI를 재사용.
- **나침반 또는 미니맵:** 화면 위쪽에 주요 장소 방향을 표시.
- **피해 숫자:** 앞면이면 금색, 상성 유리면 '약점'.
- **타이틀·저장 슬롯·게임 오버 화면.**

## 5. 맵 전체 개요

- **구조:** 둥글게 둘러싼 **산맥** 안쪽에 **성벽**이 있다. 성벽 안 북쪽에는 **성**과 그 뒤의 **눈 덮인 산지**가 있고, 남쪽에는 넓은 길(**마을 광장**)을 사이에 둔 **서쪽 마을**과 **동쪽 마을**이 있다. 성벽 바깥은 넓은 풀밭이다.
- **처리:** 산과 건물을 형태로 구분하고, 질감을 입힌 뒤 채색했다. 산은 높이별로 잔디 → 바위 → 눈, 집은 벽 5색 · 지붕 4색, 성은 석재와 슬레이트다. 겹친 면(검은 지붕)과 뒤집힌 면도 고쳤다. 충돌용 메시와 길찾기(NavMesh)는 실행 중에 만든다.
- **월드맵:** 이 맵을 비스듬히 내려다본 일러스트 지도에 주요 장소 5곳을 강조하고, 내 위치를 표시한다.
- **부족한 점:**
  - 지역마다 역할(전투 구역·안전 구역·보스 무대)이 정해져 있지 않다.
  - 바다가 없어서 바다괴물형 적을 위한 해안이나 호수 구역이 필요하다.
  - 건물 안으로 들어갈 수 없다.
  - 일부 평지붕이 어둡게 보인다.
  - 맵 하나가 통째로 렌더링되어 성능 부담이 크다.

## 6. 권장 다음 순서

1. **Unity 실행·오류 수정** → 최소 플레이 가능한 상태(전투 한 판, 고래고래 등장)를 확인한다.
2. **주인공 교체 여부 결정**(배포할 생각이라면 지금 하는 것이 가장 싸다) + 사운드 기본 세트.
3. **타이틀·저장·게임 오버** — 게임의 시작과 끝을 만든다.
4. **마을을 안전 구역으로:** NPC·대화·상점·첫 퀘스트를 넣어 RPG 뼈대를 만든다.
5. **지역 진행:** 성(인간형) → 산지(고래고래) → 해안(바다괴물형 + 보스), 구역마다 보스 무대.
6. **성장 확장:** 스킬 습득·교체, 장비 능력치, 캐릭터와 스킬 화면.
7. 밸런스 플레이테스트, 튜토리얼, 성능 최적화.
